# 接入和验证路线

以下是基于本次源码差异制定的后续实施方案，尚未执行这些固件修改或台架试验。

## 1. 先确定版本与接口

保存固件commit、构建配置、编译器版本、链接脚本、参数表哈希和电芯型号。确认当前运行设备对应哪份工程，尤其是FreeRTOS优先级配置与EVE/CATL参数宏。补齐报告中19份日志、PW3390原始记录、辨识CSV和生成/评估脚本；按测试轮次建立“源码—宏—二进制—参数—日志”对应表。

冻结输入契约：电流A且放电为正，单体电压V，温度℃，容量Ah，SOC为[0,1]；每项带有效标志与采样时间。处理-41温度等无效值，初始化后继续监控Ready/数据有效性。当前温度缩放问题必须在接入前解决。

## 2. 保持影子运行

在 `SocSoeLibAllTask` 的case2/12中接入 `EkfAdapterTask` 是候选位置，但首先测定定时器回调耗时和任务优先级。Ts=0.5s是算法假设，应记录实际调用间隔；过长时延要有明确处理策略。

第一阶段只记录，不接管容量、SOC显示、继电器或保护。影子数据至少包含：时间戳、电流、min/avg/max电压、温度、原SOC、EKF SOC、Qn、U1/U2/b、预测电压、残差、选用参数分支、输入有效性、重置原因。

## 3. 主机回放与接口检查

| 用例 | 目的 | 判断依据 |
|---|---|---|
| 25℃接口注入 | 排除温度十倍缩放 | 算法输入必须等于25℃ |
| 正负恒流 | 核对积分方向与单位 | 放电SOC下降，充电上升；与独立积分量纲相符 |
| Qn=0、负值、异常值 | 验证除零和初始化拒绝 | 不输出非有限状态；错误可追踪 |
| SOC/温度边界 | 验证查表夹限 | 端点连续，边界行为与设计一致 |
| 电流在0附近抖动 | 检验充放表切换 | 记录电压预测和SOC跳变；评估是否需滞回 |
| Ready丢失/传感器断线 | 验证降级与恢复 | 有效标志传播；不把哨兵值当正常物理量 |
| 掉电重启 | 对齐旧SOC、容量与EKF初值 | 重启状态来源和版本可追踪 |
| SOC=200/201/250/251/300/301 | 验证SOC/SOE分段逻辑 | 覆盖预期修正分支与连续性 |

这些用例是待执行验证，不附带虚构的通过率。可先对纯EKF核心建立主机回放，不依赖整板外设；接入层另做桩函数验证。

## 4. 台架验证

分别覆盖满充满放、局部循环、长静置、阶跃负载、充放切换、不同温度、不同容量状态和单体不一致。独立参考SOC需要明确初始条件、积分电流校准、容量基准与时间同步。对BMS_SOC的一致性和对独立参考的误差应分别报告。

指标包括RMSE、平均/最大偏差、分SOC区间误差、切换后的收敛时间、输出最大变化率、残差分布、偏置饱和时间和计算耗时。验收阈值由产品需求和测量不确定度确定，不能把历史某轮<2点直接设为全部工况已达标。

## 5. 再评估接管

当模型、异常策略和现场验证完成后，再定义EKF对nowCap/remCap、SOC显示、SOE同步、端点校准、持久化和保护消费端的影响。保留版本化回退与影子对照能力。是否分方向维护b、切换后冻结观测或改变Q/R，必须通过相同数据集对照验证，不能只靠一次曲线观感决定。
